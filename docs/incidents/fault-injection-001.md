## Remediation and residual risk

### model-429 — Model provider returns HTTP 429

- **Observed code:** `MODEL_RATE_LIMITED`
- **Remediation:** Exponential backoff plus jitter, with a hard max_retries ceiling.
- **Residual risk:** Sustained 429s trip the circuit breaker and surface as retryable errors.
- **Evidence:** `{"attempts": 2}`

### model-timeout — Model call exceeds its time budget

- **Observed code:** `MODEL_TIMEOUT`
- **Remediation:** Retry ceiling prevents unbounded loops; resolution is RETRY at job level.
- **Residual risk:** A slow provider keeps jobs retrying until the run budget ends.
- **Evidence:** `{"attempts": 3, "resolution": "RETRY"}`

### invalid-json — Model returns an unparsable JSON payload

- **Observed code:** `MODEL_SCHEMA_PARSE_FAILED`
- **Remediation:** Separate schema-repair budget from the transport retry budget.
- **Residual risk:** A model that never emits valid JSON exhausts the repair budget.
- **Evidence:** `{"attempts": 2}`

### broker-unavailable — Redis / Celery broker is temporarily unreachable

- **Observed code:** `BROKER_UNAVAILABLE`
- **Remediation:** Publish failure leaves the outbox row pending, so a retry re-publishes it.
- **Residual risk:** While the broker is down, new runs stay queued and must not double-publish.
- **Evidence:** `{"resolution": "BACKPRESSURE", "fallback": true}`

### worker-mid-exit — Worker process exits in the middle of a run

- **Observed code:** `WORKER_INTERRUPTED`
- **Remediation:** Checkpoint after every node; resume restores the last SUCCEEDED state.
- **Residual risk:** Nodes without an idempotent side effect would need extra dedupe guards.
- **Evidence:** `{"vlm_calls_before": 1, "vlm_calls_after": 1, "resumed_status": "SUCCEEDED"}`

### subprocess-stuck — FFmpeg subprocess ignores terminate()

- **Observed code:** `SUBPROCESS_STUCK`
- **Remediation:** terminate -> wait(timeout) -> kill -> wait(timeout); then clean the run dir.
- **Residual risk:** A process in an uninterruptible syscall may still need an OS-level reap.
- **Evidence:** `{"killed": true, "waits": [5, 5], "run_dir_removed": true}`

### object-storage-failure — Object-storage write fails during artifact publication

- **Observed code:** `OBJECT_STORAGE_ERROR`
- **Remediation:** Publish into a temporary key, then copy, then write the manifest last.
- **Residual risk:** Orphaned temporary objects still require a periodic sweeper.
- **Evidence:** `{"artifact_rows": 0}`

### db-connection-exhausted — Database connection pool is exhausted

- **Observed code:** `DB_CONNECTION_EXHAUSTED`
- **Remediation:** Fast readiness/liveness separation plus queue-level admission control.
- **Residual risk:** Long-running transactions can still hold connections until they time out.
- **Evidence:** `{"code": "DB_CONNECTION_EXHAUSTED", "retryable": true, "resolution": "BACKPRESSURE", "reason": "database refused or dropped the connection"}`

### duplicate-start — User double-clicks Start for the same job

- **Observed code:** `IDEMPOTENT_REPLAY`
- **Remediation:** Reserve the key transactionally and replay the recorded response.
- **Residual risk:** A different key with the same intent still needs a domain-level guard.
- **Evidence:** `{"executions": 1, "run_id": "run-fixed"}`

### cancel-during-run — User cancels a run that is still executing

- **Observed code:** `JOB_CANCELLED`
- **Remediation:** The worker re-checks cancellation before finalising the job row.
- **Residual risk:** Side effects already emitted must remain individually idempotent.
- **Evidence:** `{"worker_status": "SKIPPED"}`
