# Observability and operations guide

## Correlation model

Every request opens one immutable scope. Nested helpers only declare the level they change, so the
outer identifiers are always preserved.

```text
request_id            generated by the API middleware or accepted from X-Request-ID
└─ workspace_id       resolved from the authenticated workspace scope
   └─ job_id          the analysis job
      └─ run_id       the agent run (also the Celery task's correlation root)
         └─ step_id   one graph node execution
            └─ tool_call_id
               └─ model_call_id
```

`CorrelationContext.to_headers()` emits `X-Request-ID`, `X-Workspace-ID`, `X-Job-ID`, `X-Run-ID`,
`X-Step-ID`, `X-Tool-Call-ID` and `X-Model-Call-ID`. `CeleryTaskQueue` attaches those headers to the
task message; `apps/worker/celery_app.py` rebuilds the scope from them. The in-process queue cannot
rely on `contextvars` propagation across `ThreadPoolExecutor.submit`, so it captures the scope on
the producing thread and re-binds it inside the worker thread.

## Structured logs

All project logs are single-line JSON with `timestamp`, `level`, `event`, `logger`, an optional
`correlation` object and a `fields` object.

```json
{
  "event": "agent.tool.completed",
  "job_id": "...",
  "tool": "observe_visuals",
  "attempt": 1,
  "latency_ms": 3240,
  "result_count": 12
}
```

Rules enforced by `redact_value` and covered by `validate_record`:

- keys matching `secret|token|password|authorization|api_key|credential|signature|private_key`
  are replaced with `[redacted]`;
- content bodies (`prompt`, `transcript`, `chain_of_thought`, `reasoning`, `raw_media`, `*_bytes`)
  are dropped entirely;
- values are masked for data URIs, bearer tokens, `sk-` keys, emails, mainland phone numbers and
  Windows/POSIX media paths, then truncated at 512 characters.

Never log full media, full transcripts, model chain-of-thought or unmasked personal data.

## Metrics

`GET /metrics` returns the Prometheus text format. Series groups:

| Group | Examples |
|---|---|
| HTTP | `evidenceclass_http_requests_total`, `evidenceclass_http_request_milliseconds` |
| Queue | `evidenceclass_queue_in_flight`, `evidenceclass_queue_weight`, `evidenceclass_queue_rejections_total` |
| Agent runs | `evidenceclass_agent_runs_total`, `evidenceclass_agent_run_milliseconds` |
| Stages | `evidenceclass_stage_<stage>_milliseconds` (histogram per stage) |
| Benchmarks | `evidenceclass_benchmark_<scenario>_milliseconds` |
| Faults | `evidenceclass_fault_injections_total` |

### Reading the panel after one run

```powershell
python -m evals.run_stage12_panel
```

The probe executes one short job, then prints the per-stage medians taken from the same registry the
`/metrics` endpoint exposes. A live deployment scrapes `/metrics` into Prometheus and renders the
stage histograms as the operations panel.

## Reliability verdicts

`classify_infrastructure_error` maps an exception to a verdict so the API, the queue guard and the
fault report agree on the outcome:

| Condition | Code | Resolution |
|---|---|---|
| Provider 429 / timeout | `MODEL_RATE_LIMITED`, `MODEL_TIMEOUT` | `RETRY` (bounded) |
| Database pool exhausted | `DB_CONNECTION_EXHAUSTED` | `BACKPRESSURE` |
| Broker or network down | `BROKER_UNAVAILABLE` | `BACKPRESSURE` |
| Media subprocess over budget | `SUBPROCESS_STUCK` | `DEGRADE` |
| Worker process exit | `WORKER_INTERRUPTED` | `RETRY` from checkpoint |
| Unrecognized | `UNCLASSIFIED_INFRASTRUCTURE_ERROR` | `FAIL` |

## Queue protection

`QueueGuard` estimates a task weight from its duration (`1 + ceil(duration/60)` scaled per mode),
keeps a bounded self-pruning in-flight window per workspace and globally, and rejects with
`QUEUE_BACKPRESSURE` (HTTP 429, `retryable=true`, `retry_after_seconds`) once a ceiling is reached.
Single tasks beyond `max_task_seconds` or `max_task_memory_mb` are rejected with
`QUEUE_TASK_TOO_LONG` / `QUEUE_TASK_TOO_LARGE`. Repeated GPU OOM degrades the batch on the first
event and escalates to human review afterwards instead of retrying the same workload.

Tune with `EVIDENCECLASS_QUEUE_MAX_QUEUED`, `EVIDENCECLASS_QUEUE_MAX_WEIGHT` and
`EVIDENCECLASS_QUEUE_MAX_TASK_SECONDS`; disable the metrics route with
`EVIDENCECLASS_METRICS_ENABLED=0`.
