## 12.1 统一关联 ID

- 新增 `packages/observability/correlation.py`：`CorrelationContext` 承载 7 个标识
  （request_id / workspace_id / job_id / run_id / step_id / tool_call_id / model_call_id），
  基于 `contextvars` 的开闭作用域 `bind()`，`derive()` 只收窄声明层级，`from_headers()`/`to_headers()`
  做 `X-*-ID` 序列化。
- `apps/api/main.py`：中间件生成或接受 `X-Request-ID` 并绑定作用域，响应回传 `X-Request-ID` 与
  `X-Trace-ID`；CORS 放行 `X-Request-ID`。
- `apps/worker/queue.py`：`InProcessTaskQueue` 在提交线程捕获作用域，并在 worker 线程内重新绑定
  （`ThreadPoolExecutor.submit` 不会复制 contextvars）；`CeleryTaskQueue` 走 `apply_async(headers=...)`。
- `apps/worker/celery_app.py`：任务改为 `bind=True`，从 task headers 还原作用域后再执行 run/resume。

## 12.2 结构化日志

- 新增 `packages/observability/logging.py`：`JsonFormatter` 输出单行 JSON（timestamp/level/event/logger/
  correlation/fields）；`emit_event()` 强制 `agent.tool.completed` 式稳定事件名，字段经 `extra=` 传递，
  与 LogRecord 保留键冲突时加 `field_` 前缀。
- 脱敏：`secret|token|password|authorization|api_key|credential|signature|private_key` 等键整体替换为
  `[redacted]`；`prompt/transcript/chain_of_thought/reasoning/raw_media/*_bytes` 等正文键直接丢弃；
  值级掩码覆盖 data URI、Bearer、`sk-` 密钥、邮箱、手机号、Windows/POSIX 媒体路径，超长字符串截断。
- `validate_record()` 同时校验 schema 与脱敏，供测试与验收门禁使用。

## 12.3 指标面板

- 新增 `packages/observability/metrics.py`：计数器/仪表/直方图 + Prometheus 文本暴露，
  空标签聚合计（`histogram_summary()` 不传 labels 时跨标签聚合）。
- 新增 `packages/observability/timing.py`：`StageTimeline` 覆盖 11 个阶段
  （upload / queue_wait / probe / frame_extract / asr / ocr / vlm / retrieval / agent_overhead /
  artifact / end_to_end），并提供 `peak_memory_mb()` 采样（`resource` 不可用时退回 tracemalloc，
  取不到就报未知而不猜测）。
- 埋点：API 中间件记 `evidenceclass_http_requests_total` / `_http_request_milliseconds`；
  worker `_finalize_observability()` 记 runs 计数、每阶段直方图与端到端耗时；
  `admit_job()` 记 `queue_in_flight` / `queue_weight` / `queue_rejections_total`。
- 新增 `GET /metrics`（Prometheus 文本）与 `GET /api/v1/queue/status`（准入窗口快照 + 估算）。
- `evals/run_stage12_panel.py`：跑一条真实短任务后读 `/metrics`，断言
  `evidenceclass_stage_agent_overhead_milliseconds` / `..._end_to_end_milliseconds` 存在且中位数非零。

## 12.4 故障注入

- 新增 `packages/observability/reliability.py`：把基础设施异常归一到
  `RETRY / BACKPRESSURE / DEGRADE / FAIL / NEEDS_REVIEW` 五种处置。
- 新增 `packages/observability/faults.py`：10 个确定性场景，全部跑真实组件路径——
  模型 429、模型超时、非法 JSON（schema 修复）、Redis/Celery broker 不可用、Worker 中途退出
  （`WorkerInterrupted` + checkpoint 续跑且不重复 vlm 调用）、FFmpeg 卡住（terminate→kill→清理）、
  对象存储写入失败（manifest-last，Artifact 行数为 0）、数据库连接耗尽（分类为 BACKPRESSURE）、
  重复启动（Idempotency-Key 回放，副作用=1）、运行中取消（worker 不覆盖取消态）。
  每项记录注入/预期/实际/修复/残余风险。
- 新增 `evals/run_stage12_faults.py`，发布 `docs/incidents/fault-injection-001.md`。

## 12.5 性能基线

- 新增 `evals/run_stage12_benchmark.py`：固定 4 类输入（1080p 单图、2 分钟 720p、10 分钟 720p、
  46 分钟双机位压力项），每类 5 次；测量 upload（序列化+sha256+对象存储写入）、
  agent_overhead（确定性 AgentGraph + 证据引擎）、artifact（5 类产物渲染）、end_to_end、peak_memory。
- 模型相关阶段（probe/frame_extract/asr/ocr/vlm/retrieval）明确记为 `null` 并列出跳过原因，
  不冒充任何真实模型延迟或准确率；token/费用为 0（未调用付费provider）。
- 产出 `evals/reports/benchmark-v0.12.0.md` 与同名 JSON，含机器、Python、CPU、样本数与限制。

## 12.6 队列保护

- 新增 `apps/worker/admission.py`：`QueueGuard` 按 workspace 限制并发与排队数、按视频时长估算任务权重、
  设置单任务时间/内存上限、自带 TTL 剪枝的在途窗口；`on_gpu_oom()` 首次降级 batch、重复则转人工复核，
  不无限重试。
- `apps/api/main.py`：`start/retry/rerun` 先准入后建 Run；超限返回 HTTP 429 `QUEUE_BACKPRESSURE`
  （`retryable=true` + `retry_after_seconds`）；过长/过大任务返回 `QUEUE_TASK_TOO_LONG` / `QUEUE_TASK_TOO_LARGE`。
  `_job_media_hints()` 兼容严格 schema：从 `metadata.duration_seconds` / `asset_count` 读取媒体线索。
- 新增 `evals/run_stage12_load.py`：24 并发 start（httpx ASGITransport，进程内高并发）→
  实测 4 准入 / 20 拒绝、`health/live` 全程 200、`queue_in_flight` 不超上限、`/metrics` 暴露拒绝计数。
