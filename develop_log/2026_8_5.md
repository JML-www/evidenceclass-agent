## 踩坑与经验

- 旧项目脚本的文件名、函数名和对外入口需要在迁移前逐项核对。
- 旧业务脚本可能依赖硬编码相对路径，迁移时应先用测试固定行为，再调整目录。
- Windows 下执行 pytest 时需要确认仓库根目录和解释器路径。
- 测试文件被创建不等于测试已经通过；应区分“已编写”“可收集”“已执行”和“已通过”。
- 推荐的迁移节奏是：

```text
建立来源记录
  -> 准备脱敏 fixture
  -> 编写一个可失败的特征测试
  -> 迁移一个最小实现
  -> 运行专项测试
  -> 运行全量测试
  -> 提交
```
